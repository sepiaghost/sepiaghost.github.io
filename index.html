01 · privacy

Differential Privacy for Genomic Data Sharing

Quantifies the privacy-utility tradeoff in genomic data release: implements the Laplace mechanism across seven privacy budgets (ε = 0.1–10) on real RNA-seq data, then measures both how much statistical accuracy is lost and how well a simulated membership-inference attacker is actually defeated at each level.

ε 0.1–10privacy levels tested
~0.50attack accuracy under noise (vs. 1.0 unprotected)
F1 < 0.06DE-gene recovery, entire tested range

The headline finding: privacy against re-identification is cheap to buy — even light noise collapses attacker accuracy to chance — but preserving genuine scientific utility under that same noise is hard, and doesn't improve smoothly as the privacy budget relaxes.

03 · biophysics

Hodgkin-Huxley Neuron Model

A numerical implementation of the Hodgkin & Huxley (1952) model of the action potential in the squid giant axon — four coupled nonlinear ODEs, solved with an adaptive solver (deSolve::ode(), lsoda) rather than the fixed-step Euler's method used in the original hand-computed version.

A personal recreation: this started as an undergraduate biophysics assignment built by hand in Excel, assigned by the professor who is now writing one of my Ph.D. recommendation letters. Rebuilding it in R extends the original with an F-I curve sweep to locate rheobase and a double-pulse protocol to measure the absolute refractory period.

04 · deep learning & privacy

Differentially Private Deep Learning for Cancer Classification

Extends the differential-privacy work from a single released statistic to a full trained neural network: a tumor vs. normal classifier on TCGA-BRCA gene expression, trained with DP-SGD (via Opacus/PyTorch) across a sweep of privacy budgets and benchmarked against a non-private baseline.

1,231samples, top 2,000 variable genes
98.8%baseline accuracy, no privacy
ε 0.5–20DP-SGD privacy budgets tested
~0.998AUC held across the full ε range

Rather than a clean textbook tradeoff curve, accuracy fluctuates non-monotonically across epsilon values while AUC stays consistently high throughout — evidence that per-run training variance, not privacy budget, dominates at this scale, and that DP-SGD preserves near-baseline discriminative power even under tight privacy constraints.

06 · lab data integrity

Sample Tracker

A Streamlit and SQLite sample tracker built around one question: if someone edits a custody record after the fact, will you know? Every change appends a log entry whose SHA-256 hash covers the entry before it, samples are never deleted (only marked discarded), status changes follow an allowed-transition table, and subject codes must be de-identified codes, so names are rejected at the form.

SHA-256hash chain: each entry covers the one before it
5integrity checks: hashes, links, sequence, time order, inventory vs. log
1published database format, checked by a shared test fixture
34tests, including headless UI tests

Health and research labs often can't assume bank-grade security, so the goal is tamper-evident, not tamper-proof, and the README says so, listing its limits plainly (self-asserted identity, an editable database file, a head hash that has to be stored elsewhere). The database format is published, so a separate tool can verify it without trusting the app.

07 · digital forensics

Genomic Forensics Toolkit

Applies digital-forensics practice to genomic data. A dependency-free Python toolkit examines FASTQ, VCF and BAM files, repository access logs and sample custody databases, then writes an examiner-style case report: evidence hashed before and after analysis, a reconstructed timeline, and conclusions that say what the evidence does and does not prove.

3file types cross-checked against each other: FASTQ, VCF, BAM
44.5%genotype concordance of a swapped sample, vs. 98.0% for the true match (synthetic case)
9access-log detection rules, mapped to MITRE ATT&CK
69tests; BAM reader validated against pysam

A synthetic hypothetical case ties it together: a delivered BAM with a read group its header never declares, 150 reads from a foreign flowcell that exist in the FASTQ's R2 but not its R1, and a header rewritten after alignment; an access-log intrusion; and a tampered custody database whose edited entry is detected, and its original value recovered, by testing which known value reproduces the stored hash. The toolkit verifies the Sample Tracker's database with its own implementation of a published format and is tested against a fixture built by the real app. Its README adds a threat model for health-data systems with a hardening roadmap.
